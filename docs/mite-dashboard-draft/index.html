Counting methodBee tracks v1 (proposed)

Count each completed bee track once, whether or not mites are detected. Bees with mites are a subset of that total. A bee returning later can count as another passage; this is not a count of unique colony members.

Synthetic data only. No connection to the board. Missing periods are not zero counts. Bee detection and tracking are required to produce these counters. This view does not estimate colony infestation.

Proposed architecture

Detect locally. Keep the history.

One board, one durable event log, one browser dashboard.

First release: the API and webpage run on the UNO Q's Linux side. Connect over a local network; no cloud is required.

Capture → persist → explore

01 / Camera + inference

Detect and track every bee, then run the mite check on each bee crop.

→
02 / Event recorder

One event per completed bee track, including bees without detected mites and uncertain assessments.

03 / SQLite history

Durable observations, sessions and recording coverage on a persistent volume.

→
04 / Python API + page

Read totals and time buckets. Serve this dashboard alongside the existing live view.

The existing Bridge → STM32 matrix path remains. A display reset must not erase historical events.

The API the page needs

GET /api/v1/devices/{id}/summary

Total bees observed, bees with detected mites, and recording coverage for the selected range.

GET /api/v1/devices/{id}/series

Hourly or daily counts for all bees and the subset with detected mites, including recording gaps.

GET /api/v1/devices/{id}/observations

Paginated evidence events with timestamps, scores and model revisions.

GET /api/v1/devices/{id}/status

Camera, inference, recording health and the last persisted event.

GET /api/v1/devices/{id}/export.csv

The same range, source and measurement method as the chart.

Build in this order

  1. Detect and track every bee; validate passage counting.
  2. Persist all completed tracks with mite assessment.
  3. Add the read API and date aggregation for both counts.
  4. Connect the page; verify counts on the board.

When remote access is needed

Add a durable outbox → outbound HTTPS → hosted API and database. Retry by event ID so reconnects cannot duplicate counts. Show remote sync freshness separately.
